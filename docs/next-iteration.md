# 下一版功能备注

这些条目只记要做什么，这一版先不开发。当前线上是 0.1.20。做的时候编辑器仍只请求 `/wiki/*`，邀请链接如果要服务端签发，再另补 NestJS 接口说明。

每一节都可以单独放进 GitHub Project，当一张卡片。

## 团队列表和团队详情

现在团队列表只有名称、角色和「团队详情」。团队详情在右侧抽屉里，用表格列出名称、团队码、注册时间、更新时间。名称和详情都不能改。接口上已有 `description`，界面没有展示，也不能编辑。复制团队码、刷新团队码是两个文字按钮。

下一版：

- 团队列表不要只剩一行名字，信息再完整一些。
- 团队详情里，团队名称和详情可以编辑。
- 增加详情字段，把现在没露出来的说明写进去。
- 复制团队、刷新团队改成图标，不再用文字按钮。
- 团队详情不用表格。名称、详情、团队码、时间用普通信息布局，不要「字段 / 内容」两列表格。

## 团队邀请

现在只能用团队码加入：详情里看码，对方在「加入团队」里填写。没有邀请链接。

下一版在团队码之外增加链接邀请。对方打开链接即可加入团队。团队码验证保留。

## 邀请码的点击

现在要点「复制团队码」才复制，复制之后没有成功提示。

下一版：点击邀请就是复制。复制完成后要能看见「已复制」。

## 团队成员列表

现在成员一次全部列出来，不能搜，也没有分页。列是成员、注册时间、角色。

下一版：

- 按成员名称搜索。
- 成员多的时候分页。

## 成员表格

现在这张表不好看，也没有成员状态。

下一版把表格做完整：样式重新排，该有的操作补上，并增加状态。状态具体有哪些取值，开发前再定，文档里先记「需要状态」这一列。

## 团队角色说明

现在角色只有三个名字：拥有者、开发者、使用者。界面上没有说明各自能做什么。

现有能力，说明文案按这个写：

- 拥有者：可以写团队文章，可以改成员角色、刷新团队码、解散团队。
- 开发者：可以写团队文章，不能管理成员。
- 使用者：只能查看团队文章。

下一版在角色旁边放功能说明，让人选角色时知道差别。不在这一轮改权限本身。

## 侧边栏在移动端的菜单

桌面端侧边栏的「更多」仍可以用现在的下拉菜单。移动端不要再用 Popover 或贴在按钮旁的下拉层，改成从底部弹出的 Bottom Sheet。范围是侧边栏里的菜单：页面更多、分区更多、团队更多。
